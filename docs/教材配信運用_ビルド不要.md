# ネパール語アプリの教材と音声の配信運用

ユーザー決定：教材・例題・対訳・辞書・音声の更新だけで、アプリのビルドを行わない。アプリ2.1.4の既存の読込機能で反映する。

## ビルドの境界

| 変更するもの | 反映方法 |
|---|---|
| 教材本文、既存の段落・表・見出しを使う説明 | 配信JSONだけを更新 |
| 例題の追加、削除、並び替え、訳、読み、辞書 | 配信JSONと対応表を更新 |
| 既存の画面で扱えるテーマの追加や構成 | 配信JSONを更新し、例題数・参照先を検証 |
| 音声の追加・差し替え | 新しい固定録音IDで音声を登録し、音声パックと参照表を更新 |
| 新しい画面部品、操作機能、SDK、権限など | 本当にアプリコードの変更が必要な場合だけビルド。必要な理由を先に説明 |

教材更新でapp.jsonのversionやGitHub Actionsのrun-nameを上げない。workflowを起動しない。教材パック版と音声版だけを上げる。

## 前回ビルドが必要になった理由

旧構造では例題の位置から音声ファイル名を決めていた。例題を並び替えるだけでも旧音声と食い違うため、2.1.4で例題IDと固定録音IDを分離した。この読込機能の追加はアプリコードの変更だった。

2.1.4の読込機能は、配信されたgrammarAudioRefsで音声を解決する。今後の通常の教材・音声編集のたびに、殻を変更する必要はない。

## 録音と配信のルール

- 既存録音のIDとファイル内容は固定する。表示順の番号を録音IDだと推測しない。
- 新しい録音は900-で始まる独立IDで保存し、表示本文・実際の読み上げ本文・声・速度・ファイルのSHA256を台帳に記録する。
- 差し替えたい場合も新しい録音IDを作り、参照先だけを変更する。過去に配った同じIDの録音を上書きしない。
- 教材版と日英パック版を一致させる。新しい録音がない例題にはnullを設定できるが、音声も依頼された更新では全例題の対応を確認する。
- ファイル名に版番号を付けた配信資産を先にアップロードし、最後にcatalog.jsonだけを更新する。旧資産は保持する。
- 配信中の殻を再ビルドせず、実際のloadPack経路で新規取得・旧キャッシュからの更新をテストする。

## 使用する既存ツール

- 音声生成：`聞いて話せるネパール語/scripts/_regen_colored_appa.mjs --manifest <JSON>`。ne=Hemkala標準速度、ja=Neural2-B、en=Wavenet-F。APIキーは既存の.envから読み、出力しない。
- 音声台帳：`聞いて話せるネパール語/文法教材/grammar_recordings_v3.json`。台帳のspokenは説明用の括弧書き等を除いた実際の読み上げ本文。
- 教材生成：`build_grammar_revision.py`。`GRAMMAR_PACK_REVISION`に次の教材版を指定できる。未指定では保存済みの版の次を使う。新しい台帳を参照し、例題と録音を結び付ける。
- 音声圧縮：既存の`build_appa_packs_32k.py --base-dir <旧ZIP3本のフォルダ>`。固定IDの旧MP3は配信済みバイトを再利用し、新規分だけを32k化する。音声パックの処理であり、アプリのビルドではない。
- 音声追加の配信準備：`package_grammar_audio_update.py`。旧MP3が変わっていないことを全件照合し、版番号入りの資産とカタログを作る。
- 検証：`verify_grammar_revision.cjs`。既存2.1.4の読込コードをそのまま使い、日英の本文・音声・キャッシュ更新を確認する。

従来の音声パックスクリプトの`--publish`は旧v2向け。v3ではこの運用に従い、版番号入り資産を公開した後にカタログを更新する。
