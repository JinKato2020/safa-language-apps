# 教材と音声の配信運用（ビルド不要）

教材・例文・翻訳・辞書・音声は、既存の殻が読む形式にそろえてセットで配信する。通常のコンテンツ更新でアプリ版を上げたり、ビルドworkflowを起動したりしない。新UIやSDKなど実際の殻の変更が必要な場合だけ、その理由を先に説明する。ビルドを開始した場合もユーザー指示に従い追跡しない。

## 既存アプリの形式を優先

2.1.3は例文の位置から「テーマ番号-例文番号.mp3」を読む。例題を追加・変更・並べ替えたときは、本文・日英訳・教材解説・辞書と、その位置で読む3言語のMP3をまとめて更新する。この方法に追加の音声参照機能や新しい殻は必要ない。

2.1.4の音声参照機能は過去の実装判断であり、教材更新の必須条件ではなかった。今回の配信データにはgrammarAudioRefsを含めず、2.1.3の既存方式に統一する。2.1.4も参照表がなければ既存方式で読める。v2とv3のcatalogは同じ教材・音声セットを指す。

## 原本と配信ファイル

録音原本は固定台帳の本文・声・速度・SHA256とともに保持する。原本の録音IDは制作管理用。配信ZIPを作る段階で現在の例題の位置に対応するファイル名にコピーする。既存原本の上書きや不要な再生成はしない。

- 音声生成：`聞いて話せるネパール語/scripts/_regen_colored_appa.mjs --manifest <JSON>`。ne=Hemkala標準速度、ja=Neural2-B、en=Wavenet-F。キーは出力しない。
- 教材生成：`build_grammar_revision.py`。出力は制作中間データであり、固定録音IDのまま既存アプリへ直接公開しない。
- 音声圧縮：`build_appa_packs_32k.py --base-dir <旧ZIPフォルダ>`。会話など既存MP3はバイトを保持して再利用する。
- 既存形式への配信準備：`package_positional_grammar_update.py`。`--source-dir`は制作JSONとcatalog、`--previous-dir`は配信中v2のJSONとcatalog、`--audio-dir`は原本IDの圧縮済みZIP、`--output-dir`と`--revision`を指定する。
- 検証：`verify_positional_grammar_update.cjs <作業フォルダ>`。publish/、v2/があるフォルダを指定。実際の2.1.3（commit89c0982a）と2.1.4ローダーで日英・新規取得・旧キャッシュ更新・オフライン再読込を確認する。ZIPを実際に展開し全例題の音声ハッシュまで一致を確認する。

本文・日英訳・解説・辞書と全例題の音声の一致を検証してから、版番号付きの6資産をpacks-appa-v2に先に公開する。旧資産は保持する。最後にv2とv3のcatalog.jsonを同じ新しい目録へ更新する。アプリは起動時に更新を取得する。

## ホーム・入門順序・復習と自動OTA（アプリ2.1.12／教材1214）

ホームを追加し、タブはホーム・文法・会話・聞き流し・単語の5つ。設定はホーム右上。「はじめての7ステップ」は既存のテーマ番号を変えず、文法1〜6と自己紹介から各5文を選ぶ。発音・ローマ字・鼻母音などの短い導入、教材へのリンク、5文の練習、前回の続き、5問以下の復習を結ぶ。日英の学習順序・例題参照は同一。

答えを見た後の「できた／もう一度」は端末のAsyncStorageへ保存する。「もう一度」を優先し、「できた」は1・3・7日後に再出題。同日反復で間隔を飛ばさない。練習済みは全5文を自己評価した印で、正答率や習得保証ではない。再起動・言語切替でも記録を保持し、同じIDのネパール語本文が変わったら古い評価を流用しない。保存失敗時は成功扱いにせず、教材を表示しただけでは練習済みにしない。

文法の動詞186文脈を確認し、日英の辞書と例題の単語表を文脈に合わせた。正本は文法教材/grammar_context_corrections.json。IDとネパール語本文の一致を条件にし、再生成でも汎用訳へ戻らない。全528例題、会話1,800文、単語1,000語、音声は保持。テーマ・レベル・カテゴリ名も配信データから表示する。

### 2.1.12以降のコンテンツ配信

JLPTのファイルハッシュによる差分配信を参考に、App A専用のcontent/ota.tsを採用。ネイティブの画面・処理はビルドし、教材・例題・翻訳・辞書・学習順序・ポスターの情報はJSONで配信する。教材の画像は従来のURL・ハッシュ付き画像キャッシュ、ポスター資源は既存の自動取得を継続。新しい表示形式や画面機能の追加はビルドが必要。

初回用の日英教材を同梱し、ダウンロード確認画面を廃止。初回から本文を開け、音声は裏で自動準備する。既存利用者の音声はサイズとハッシュの一致を確認して再利用。新しい教材は裏で取得し、音声まで揃った組を次回起動時に適用する。同じ本文版の初回音声準備だけは、その場で再生可能にする。オフライン時は取得済みの組、なければ同梱教材で起動する。

配信先はGitHub Release `packs-appa-ota` の `manifest.json`。本文はコア・母語オーバーレイ・各テーマの教材に分割し、不変URLとSHA-256で管理する。変更のない教材や音声は再取得しない。音声アーカイブと展開ファイルはSHA-256を照合し、文と音声IDの対応を確認する。既存音声の再利用はnativeのMD5・サイズ比較を使用。音声の配信元は従来のバージョン付きzipを維持し、差分zipの指定も利用可能。

内容は不変のキャッシュへ準備し、すべて成功してから小さい参照ポインターを切り替える。失敗時に現在の教材や音声を上書きしない。直前の正常な組も保持し、不正なハッシュ・翻訳件数・音声参照・古い版を適用しない。バックグラウンドで取得した本文を学習中に突然入れ替えない。

通常の配信は、正本のJSONを更新した後に以下を実行する。版を省略すると公開版から1つ進める。`-DryRun`なら生成と検証だけで公開しない。ネイティブビルドは起動しない。

```powershell
& '.\聞いて話せるネパール語\scripts\publish_content_ota.ps1'
```

教材正本はexpo-app/data/overlays/ja.json・en.json、コアはexpo-app/data/ota-baseline/core.json。入門順序の編集元は文法教材/beginner_learning_path.json。既存の教材生成ツールでオーバーレイを再生成する場合も、配信前に入門順序・ポスター情報を保持すること。build_content_ota.pyがハッシュ付き配信ファイルを再生成し、verify_content_release.pyが全文・訳・音声参照を検証する。公開ツールは各本文の公開後ハッシュを照合してから、最後にmanifestを切り替える。

音声を変える場合は従来の生成・パック化手順を使用し、catalogの音声URL/版と、実際のzipから作るota_audio_index.jsonを更新する（build_content_ota.pyの--archives）。教材だけの変更に音声の再生成は不要。旧2.1.11以前向けのpacks-appa-v2/v3も移行期間は維持する。今回1214は旧形式と新OTAの両方へ公開する。

検証は実際の画面部品を使った日英7ステップの操作、35文ずつの評価と再開、全72教材・360表示条件、実React Navigationルーター、保存失敗・通信断・ハッシュ不一致・差分取得・直前版復旧・旧音声移行、4アプリの型検査、iOS/Hermes書き出し。ブラウザーのDOMアダプター検証とiPhone実機検証は区別する。ビルドは既存ios-build-nepali.ymlで一度だけ開始し、追跡しない。

### 2.1.13：OTA処理中の応答性

2.1.12には音声zip全体をBase64文字列・バイト列・展開済み全ファイルとして一括処理する実装があり、タップを扱うJSスレッドを長く占有していた。また5分ごとの更新確認で、変更がなくても保存済み教材の再検証・再構成が走り、AppDataの参照も変わっていた。機能テストではこの応答時間を検出できていなかった。

2.1.13はzipを32KBずつ読み、ストリーム展開して1ファイルずつ保存する。ハッシュ・Base64処理も分割し、約6msの処理ごとにイベントループへ制御を返す。全zipと各MP3のハッシュ照合・音声完了後の原子的切り替えは維持。共通音声の同時取得をまとめ、同じmanifestなら検証済みAppDataをそのまま返す（教材読み直し・音声走査・再構成なし）。再起動時はディスクの検証を行い、破損時の直前版復旧を維持する。

更新確認は起動後と、前回成功から30分以上経過してフォアグラウンドへ戻った時。学習中の定期ポーリングはしない。失敗時のみ60秒後に再試行し、バックグラウンド中は実行しない。タップやタブ移動からOTA処理は呼ばない。

verify_ota_responsiveness.cjsは実際のOTA実装に約38MB・2,328ファイルを与え、イベントループ応答・読取上限・全ファイル一致・ZIP/個別ハッシュ・DEFLATE・Unicode・更新スケジュールを検証する。verify_content_ota.cjsは従来の復旧テストに加え、変更なし確認でディスク読取ゼロ・AppData同一参照を確認。測定値はPC上の再現試験であり、iPhoneのタブ応答時間を保証する値ではない。教材1214・例文・音声は変更せず、処理修正は殻の2.1.13ビルドで配布する。

### 2.1.14：継続を中心にしたホーム

ホーム内の4つのモードカードを削除。ボトムタブは維持し、ヒマラヤの写真とネイビー・青緑を使ったホームへ変更。「今日の5文」の目標、直近7日の記録、連続日数、取り組んだ例文数、入門7ステップの進捗、再開・復習への実動作をまとめる。設定は写真右上。日英両対応。

学習記録は既存learning_v1の保存へ日別activityを追加し、「できた／もう一度」の保存成功時だけ数える。同じ例文は同じ日に1件、別の日の復習はその日の記録になる。ホーム表示では記録を増やさない。既存ユーザーは各例文の最後の評価日時から確認できる日だけを引き継ぐ（過去の全練習履歴は復元できない）。連続日数は端末の現地日付で計算し、日付変更・アプリ復帰・ホーム再表示時に更新する。失敗時の保存保証、日英切替、前回の続きは保持。

実画面コードによる日英の7ステップ・各35文、再開、復習、設定、保存失敗、小画面・大文字・横画面24条件を検証。日別重複、履歴移行、連続日数、夏時間境界は状態テスト。プレビューのprogress画像はテスト用の3日分の記録で、利用者の実績ではない。4プロジェクトの型検査とiOS/Hermes書き出しを確認。今回は表示コード・記録処理の変更なので2.1.14の殻をビルドし、教材1214と音声は変えない。


## 段階練習と教材の役割分離（アプリ2.1.15／OTA1215）

教材は基本ルール・活用表・使い分け・文化カードに絞り、説明用の短い見本は残す。全例題を繰り返す「例題1…」の一覧と、長い「復習する教材」「自分で組み立てる練習」は外した。文法モードの既存528例題・母語訳・辞書・3言語音声は保持。「例題と音声を見る」から、訳を最初から見ながら読める専用画面へ移動する。

既存7マイルストーンに、例題集と同一の文を使わない21文（各3文）の練習専用教材を追加。まず単語・読み・母語訳と文の見本を確認し、①活用選択 → ②意味選択 → ③語順パズルと進む。活用選択は主語と場面の組み合わせを教える基本テーマ1〜4の該当文に適用し、それ以外は意味選択から始める。語順パズルは「見本の基本語順」の再構成であり、別の語順をネパール語として誤りと断定しない。問題中も単語の説明へ戻れ、見本を使った完了を許す。自由作文を重複実装せず、慣れた人向けに既存の文法例題へつなぐ。

記録は supported（見本つきで確認）と known/again（自力での振り返り）を区別。supported を「習得」「話せる」と表示せず、翌日の復習対象にする。ホームの活動日・確認文数・マイルストーンは保存に成功した実際の学習記録だけを使う。音声だけの聞き取りは追加候補で、初回必須段階にはしていない。

発音導入は6カード、異なる音声10種類。新練習文21音声と合わせて31本・407,952バイトを Azure ne-NP-HemkalaNeural、標準速度0%で収録。単独の音と全文の音を区別して表示し、導入画面内で再生できる。31音声を同梱し、新しい差し替え音声は独立したハッシュ付きMP3として取得・検証・キャッシュする。従来の大型音声ZIPは再作成しない。

新しい問題・単語訳・選択肢・音声は overlay.learningPathV2 から読む。旧アプリ用 learningPath（従来35文）は保持するため、2.1.12〜2.1.14がOTAを取得しても学習経路を壊さない。2.1.15のcomposeだけがV2を優先する。今回のみ新UIを載せる殻の更新が必要。以後、このデータ形式内の問題や音声の入替はOTAで行う。

原本と手順：

- `文法教材/learning_practice_source.json`：21文の日英訳・語ごとの意味・読み。
- `scripts/build_scaffolded_learning.py`：原本から導入・問題を生成。既存例題との完全重複を検出する。`--package 1215`で教材・OTA入力を更新。
- `scripts/generate_learning_audio.mjs`：既存と同じAzure声・速度・形式。キーを出さず、台帳のハッシュが同じ録音は再生成しない。
- `scripts/publish_content_ota.ps1`：31音声→75教材チャンク→目録の順で公開。公開した全ファイルを再取得しハッシュを確認してから目録を切り替える。
- `verify_scaffolded_learning.cjs`、`verify_learning_ui.cjs`、`verify_beginner_reader.cjs`：新旧経路・語の意味・実際の操作・保存失敗・音声キャッシュ・日英の表示を検証。

検証：日英7×3文の全段階操作、24画面条件、教材72件×5条件＝360表示、182開閉、既存OTAの失敗復旧、共有/A/B/Cの型検査、iOS Hermes出力。31MP3を全件デコードし24kHzとハッシュを確認。実機操作・ネパール語母語話者による音素確認は未実施。
